# Ключевые концепции

## Проект

Проект — это контейнер для всего, что связано с одним видео. Имеет lifecycle-статус,
ссылку на брендинг и рабочую директорию.

```
created → recording → recorded → composing → rendered → published
```

Каждый переход — осмысленный: нельзя рендерить проект без записи, нельзя публиковать
без рендера.

---

## Два таймлайна

Это центральный архитектурный принцип. Их нельзя смешивать.

### 1. Лог событий записи

**Что это:** пассивный журнал всего, что происходило во время записи экрана.
Привязан к реальному времени записи (секунды сырого клипа).

**Кто пишет:** AI-агент во время записи через `log_event()`, а также автоматически
при старте/стопе записи и снятии скриншотов.

**Важное свойство: append-only.** В лог только добавляют, никогда не меняют.
Это история — как git-коммиты. Если нужно исправить — добавляют корректирующее событие
со ссылкой на предыдущее.

```
t=0      recording_started
t=120    section        "Открываем auth.py"
t=145    screenshot     asset_id=ast_screen_1
t=510    code_snippet   asset_id=ast_code_1
t=900    section        "Нашли баг"
t=2400   recording_stopped
```

**Для чего используется:** AI анализирует лог после записи, чтобы понять
какие моменты интересны и где резать при монтаже.

---

### 2. Монтажный таймлайн

**Что это:** декларативная инструкция для рендерера — как собрать финальное видео.
Время здесь — секунды **финального видео**, а не сырой записи.

**Кто пишет:** AI-агент в фазе монтажа через `timeline_add_*` инструменты.

**Структура:** фоновый слой + объекты поверх + аудио-дорожки + переходы.

```
Фон:      [raw_clip 8:00-9:30] → секунды 0-90 финального видео
          [color #121219]      → секунды 90-120
          [arch_diagram.png]   → секунды 120-180

Объекты:  text "Анализ бага"  z=1  0:00-0:05  top_left
          screenshot           z=2  1:00-1:15  right
          code_diff            z=2  1:30-1:55  left
          meme:thinking_guy    z=2  1:50-1:55  corner
          lower_third          z=10 0:00-3:00  (брендинг)

Аудио:    tts_intro.mp3   start=0    duck_main
          sfx:drum_hit    start=90   add
          music:lofi_bg   start=0    add  vol=0.15

Переходы: fade после bg1
          wipeleft после bg2
```

**Связь с логом событий:** лог подсказывает AI, где интересные моменты.
Но монтажный таймлайн — независимая структура. Финальное видео может не иметь
ничего общего с хронологией записи (куски переставлены, вырезаны, добавлен
контент которого не было при записи).

## Объектная модель (слои)

Финальный кадр — это стек слоёв, где каждый объект имеет позицию и z-индекс.

```
Z=0   Фон: видео-клип / картинка / цвет
Z=1+  Объекты: text, image, code_block, diagram, meme, sticker, ...
Z=10  Брендинг: lower_third, watermark (всегда сверху)
```

Нет понятия "слайд". "Слайд" — это просто `image` на весь экран (fullscreen) в
качестве фона + `text`-объекты поверх. Разница в гибкости:

| Слайд (старый подход) | Объектная модель |
|---|---|
| Текст только на белом/тёмном фоне | Текст поверх видео, картинки, чего угодно |
| Фиксированный layout | Любая позиция и размер |
| Нельзя смешать с видео | Объекты поверх живого видео |
| Один тип контента на экране | Несколько объектов разных типов одновременно |

### Типы объектов

| Тип | Описание |
|---|---|
| `text` | Текст с брендинговым или кастомным стилем |
| `image` | Любая картинка: скриншот, AI-изображение, схема, лого |
| `code_block` | Синтаксически подсвеченный код или diff |
| `lower_third` | Брендинговая плашка: имя + должность + лого |
| `plate` | Брендинговая плашка-карточка из конфига брендинга |
| `meme` | Картинка/GIF из медиабиблиотеки |
| `sticker` | Анимированный GIF из медиабиблиотеки |
| `shape` | Прямоугольник, круг, линия (для аннотаций) |
| `progress_bar` | Индикатор прогресса |

## Активы

Актив — это любой медиафайл, зарегистрированный в проекте.

```
raw_clip         → сырая запись экрана
screenshot       → скриншот
code_diff        → PNG с diff файла
code_snapshot    → PNG с синтаксической подсветкой кода
terminal_capture → PNG с выводом терминала
git_log          → PNG с историей коммитов
diagram          → PNG с диаграммой (bar chart, flowchart, таблица)
tts              → MP3 с озвучкой
image_ai         → AI-сгенерированное изображение
```

Активы создаются через инструменты генерации и потом вставляются в монтажный таймлайн
по `asset_id`.

## Брендинг

Брендинг задаётся в конфиге администратором. AI только **читает** и **использует**.

Что доступно из брендинга:
- Шрифты (title, subtitle, body, code, caption)
- Цветовая палитра (primary, accent, background, text, muted)
- Плашки (lower_third, section_card, quote_card, fact_card, cta_card)
- Медиа (intro-клип, outro-клип, брендинговые перебивки)
- Watermark (лого с настройками позиции и прозрачности)

При добавлении объектов AI ссылается на стиль из брендинга:
`style="branding.title"` вместо явных значений шрифта и цвета.

Подробнее: [branding.md](branding.md)

## Медиабиблиотека

Отдельная от проекта коллекция готовых материалов. AI ищет по тегам и вставляет
в таймлайн через ссылки `lib:категория/id`.

Категории: memes, sfx, stickers, cutaways, music.

Подробнее: [library.md](library.md)

## Предпросмотр как петля обратной связи

Ключевая особенность системы: AI не слеп во время монтажа.

`preview_frame(project_id, at_seconds)` — быстрый рендер одного кадра в PNG.
Не нужно ждать полного рендера (минуты) — достаточно секунды для одного кадра.

Цикл монтажа:
```
добавить объект → preview_frame → "не так" → поправить → preview_frame → "ок"
                                                                          ↓
                                                                       render()
```
